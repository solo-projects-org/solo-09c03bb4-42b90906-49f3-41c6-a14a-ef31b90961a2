# 冷链记录仪校时平台

单台冷链温度记录仪的校时网页：记录仪断电重启后时钟失准，数据员上传原始 CSV
（开机段号、本地秒数、温度），再为每个开机段录入两枚「本地秒数 ↔ UTC」校时锚点，
系统对两锚点之间的读数做线性校时，质检组即可按 UTC 日期读取可信的温度原始点。

技术栈：FastAPI + SQLite（WAL），服务端渲染页面 + JSON API，后台线程异步重算。

## 快速启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据持久化在命名卷 `coldchain-data`（容器内 `/data/app.db`）。

本地开发（无需 Docker）：

```bash
pip install -r requirements-dev.txt
uvicorn app.main:app --reload        # http://localhost:8000
pytest -q                            # 运行自测
```

## 使用流程

1. **上传数据**（`/upload`）：CSV 三列 `segment,local_seconds,temperature`
   （支持中文表头 `开机段号,本地秒数,温度`，也支持无表头按此顺序）。
   - 累计最多 **2000** 点，超限整批拒绝；
   - 同一开机段内本地秒数不能重复（文件内或与已有数据），冲突整批拒绝；
   - 每批分配批次号，行号为 CSV 数据行序号（从 1 起）。
2. **校时锚点**（`/anchors`）：每段录入两枚锚点（本地秒数 1 < 本地秒数 2，
   且 UTC 必须递增）。两锚点之间的读数按线性插值校时；范围外或无锚点的读数
   **留存待校时**。**更正锚点必须提交所见版本**（乐观并发，版本不符返回 409）。
3. **故障隔离**（`/isolations`）：每段最多登记一段有效故障区间（本地秒数**闭区间**）
   及原因，并可随时按所见版本更正或解除。
   - 区间内的原始点不进入可交付的按日供数，但保留批次号、原行号和原因供追溯；
   - 尚未校时的点日后进入锚点范围时，仍沿用同一隔离决定（隔离优先于校时）；
   - 更正/解除均为乐观并发：版本不符返回 409，**原决定保持不变**；
   - 解除后原始点在下一次换版时恢复供数。
4. **按日查询**（`/query`）：按 UTC 日期查看已校时读数，每行显示
   **批次号、原行号、锚点版本**、校时版本；隔离明细与本页可交付读数同版本展示；
   若有变更尚未换版，旧版标为**不可交付**，仅供回看。页面下方列出待校时读数及原因。
5. **处理状态**（`/`）：点数、隔离点数、重算状态（空闲/重算中/失败）、校时版本、
   数据代次、锚点、隔离记录与批次列表，可手动触发重算。

## 一致性设计

- **原子换版**：每次重算结果在单个事务内整体替换。读数跨日时，
  「旧日移除 + 新日加入」同事务生效；**校时日期、可交付读数与隔离明细**
  （`calibrated` + `isolated_points`）在同一事务一起换版；
  计算或提交失败时旧版本原样保留，**绝不提供半版**。
- **迟到计算不回退**：上传/锚点/隔离变更都递增 `state_generation`；重算按一致快照
  计算，提交前复核代次，已过期则丢弃重算 —— 迟到的重算不得覆盖新的隔离决定。
  校时版本号单调递增；隔离记录自身版本号也单调递增。
- **重算期间可写可读**：重算在后台线程进行，期间可继续上传新点，
  查询始终看到完整的旧版本；新点在随后的换版中生效。
- **重启恢复**：代次持久化于 SQLite，服务重启后自动比对并补算——
  所有已接纳且处于锚点范围内的点最终都会进入当前版。

## JSON API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/uploads` | 上传 CSV（multipart `file`），返回 `{batch_id, accepted}` |
| POST | `/api/anchors` | 录入/更正锚点 `{segment, local1, utc1, local2, utc2, version?}` |
| GET | `/api/isolations` | 隔离记录（含已解除）与当前版隔离明细 |
| POST | `/api/isolations` | 登记/更正隔离 `{segment, local_start, local_end, reason, version?}` |
| POST | `/api/isolations/clear` | 按所见版本解除隔离 `{segment, version}` |
| GET | `/api/readings?date=YYYY-MM-DD` | 按 UTC 日查询已校时读数（含隔离明细与 `deliverable`） |
| GET | `/api/pending` | 待校时读数及原因 |
| GET | `/api/status` | 点数、重算状态、代次、锚点、隔离、批次 |
| POST | `/api/recalc` | 手动触发重算 |

错误返回 `{detail, code, errors?, current_version?}`；锚点/隔离版本冲突为 409。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_PATH` | `data/app.db`（容器内 `/data/app.db`） | SQLite 路径 |
| `MAX_POINTS` | `2000` | 累计点数上限 |
| `WORKER_ENABLED` | `1` | `0` 时关闭后台线程，变更后同步重算（测试用） |
| `RECALC_DELAY` | `0` | 重算提交前人为延迟秒数（演示/测试并发窗口） |

## 已知边界

- 面向单台记录仪、≤2000 点的场景，全量重算代价可忽略，未做增量计算。
- 隔离只保留每段最近一次决定（含已解除记录），不保留逐次变更历史；
  已交付给外部系统的历史文件不在本系统可撤回范围内。
- 校时结果毫秒精度；锚点区间与隔离区间均按闭区间处理。
- 未实现鉴权与多用户，部署在内网/受信环境。
